# 高精度字幕验证记录

当前实现可选择完全本地的 Qwen3-ASR 1.7B 或 FireRedASR2-AED，均使用 Qwen3-ForcedAligner 0.6B，保留原 Paraformer 作为快捷模式。本机重构升级版已选择 FireRed，源码全新配置继续使用 Qwen。剪映完整实现和实际模型版本没有得到公开确认；本项目没有把其他商业 API 的分数当作剪映分数。

字幕体验同时受文字识别、上下文、断句、音频时间轴和字词对齐影响。本次除了比较模型，也实际修复了抽取音频后时间收缩、按字数拆断中文词语、零时长语气词导致后句丢失等问题。

## 2026-10-14 重构后的 FireRed 比较

沿用相同的固定 256 段、1194.964 秒、5295 个参考字符。音频 ID 和 SHA-256 全部匹配，识别任务没有参考文本；开启 Hugging Face/Transformers 离线模式，经新 EXE 的实际父子进程完成 FireRed CPU FP32 识别和 Qwen 对齐。

| 模型 | 成功样本 | 字级错误 | 原文 CER | 最终字幕 CER |
| --- | ---: | ---: | ---: | ---: |
| Qwen3-ASR 1.7B 基线 | 256/256 | 266 | 5.0236% | 5.0236% |
| FireRedASR2-AED | 256/256 | 240 | 4.5326% | 4.5326% |

本组少 26 个错误，相对减少 9.77%；51 段改善、169 段相同、36 段变差。按相邻四段分组、分测试集进行 10000 次配对 bootstrap（seed 20261008），CER 改善的 95% 区间为 **-0.0606 至 1.0397 个百分点**，仍跨零。因此这是固定样本上的较低实测错误率，不是普遍显著优势的证明。按用户准确率优先、允许更慢的选择，本机升级版选择 FireRed，并保留 Qwen 回退；源代码全新配置和旧配置迁移默认仍为 Qwen。

FireRed 加独立对齐共 1589.841 秒，生成 430 条字幕，256 段的归一化文字全部保留，字幕时间均有正时长、在音频范围内且起点有序。FireRed 子进程记录耗时 1393.255 秒、峰值工作集 9,987,108,864 字节；该值不是整个应用的合计峰值。旧 Qwen 基线记录总耗时 929.817 秒。不同轮次的耗时仅为本机观测，不能据此保证数小时录播的处理倍数。FireRed 原生字词时间在 256 段均通过覆盖和范围验证，但本轮最终字幕统一采用 Qwen 对齐；没有人工时间参考，不能据此宣称词边界准确率。

使用 [录播助手-重构升级版-v2.exe](G:/录播助手/录播助手-重构升级版-v2.exe)；原有三款启动 EXE 的哈希保持不变。详细重构和发行检查见 [重构验证记录](REFACTOR_VALIDATION.md)。以下 Qwen 的整场验证属于本次重构前的历史基线，不能直接算作新版 FireRed 的长录播验证。

## 扩展同音频对比：256 段

按固定规则扩大到 TEST_NET、TEST_MEETING 各 128 段，共 1194.96 秒音频、5,295 个归一化参考字符。每种方案使用完全相同的音频，256/256 均成功。

| 方案 | 字级错误数 | 字错率 CER | 实际字幕字错率 |
|---|---:|---:|---:|
| 原 Paraformer | 398 | 7.52% | 7.52% |
| Qwen3-ASR 1.7B + 独立对齐 | **266** | **5.02%** | **5.02%** |

本组少 132 个字级错误，相对减少约 33%；78 段改善、156 段相同、22 段变差。以相邻 4 段为一组、按测试集分层进行 10,000 次配对 bootstrap，CER 改善的 95% 区间约为 1.59–3.66 个百分点。此结果支持在选定样本上改善；不表示所有素材都提升，也没有测量剪映。

完整记录在 `G:\录播助手\asr_benchmark\wenet256`。抽样在新推理前固定，数据服务限流时等待后续传，没有因结果好坏更换样本。扩展集与首轮有少量重合。

## 首轮模型筛选：64 段

在运行任何候选之前，固定抽取 WenetSpeech TEST_NET 和 TEST_MEETING 各 32 段，每个测试集取 8 个均匀分布的位置、每处 4 段连续片段。共 343.97 秒音频，归一化参考文字 1,466 字。参考来自数据集，没有把参考文本传给识别模型。

| 方案 | 成功样本 | 字错率 CER |
|---|---:|---:|
| 原 Paraformer | 64/64 | 7.64% |
| Qwen3-ASR 1.7B | 64/64 | **6.34%** |
| Fun-ASR-Nano 2512 | 64/64 | 8.46% |

Qwen 在这组样本中少了 19 个字级错误，相对减少约 17%；20 段改善、37 段相同、7 段变差。该小样本不能代表整个测试集或所有录播。按相邻 4 段分组、分测试集进行 10,000 次配对 bootstrap，CER 改善的 95% 区间为约 -0.21 至 3.53 个百分点，仍跨过零，不能宣称普遍显著优于原方案。

归一化仅统一 Unicode/大小写并去掉标点、空白等；不把“三”自动改成“3”。评分会同时检查实际字幕文字，避免原始识别正确却在字幕整理中丢字。缺失或失败样本不能得到完整语料分数。

资料：`G:\录播助手\asr_benchmark\wenet64` 中的 `manifest.json`、各模型 `*-result.json`、`*-scores.json` 和 `paired-comparison.json`。

## 真实录播与时间轴

从用户同场录播的剪辑版取 9 个 20 秒片段，覆盖前、中、后段，三个引擎均完成。没有人工校对参考或剪映 SRT，因此没有给这些片段编造准确率。

整场视频的有效音轨时间为约 2936.3747 秒。旧方式抽出的 WAV 只有 2935.296 秒；修改为按媒体时间戳异步重采样后，WAV 为 2936.3746875 秒。

将原视频在多个时间点独立截取的音频，与整场 WAV 做波形相关匹配：

| 视频位置（秒） | 旧 WAV 偏移 | 修复后 WAV 偏移 |
|---:|---:|---:|
| 60 | 0 ms | 0 ms |
| 420 | 0 ms | 0 ms |
| 1140 | 0 ms | 0 ms |
| 1860 | -1078.688 ms | 0 ms |
| 2580 | -1078.688 ms | 0 ms |
| 2900 | -1078.688 ms | 0 ms |

修复后这六处波形匹配相关系数均为 1.0。这里验证的是识别音频与视频时间轴的对应关系，不等于每个模型预测的词边界都已经人工校准。另有实际 FFmpeg 回归用例：带开头延迟和内部间隙的 12 秒时间轴，旧逻辑抽成 7 秒，修复后保留 12 秒和正确静音位置。

## 长音频、断句与运行可靠性

- 136 秒受控语音：同一段话分别放在开头和 125 秒处，通过新程序的父进程、子进程和时间对齐全流程，得到两组相同的 4 句字幕。对应起止时间的间隔误差最多约 40 ms；中间静音未产生额外字幕。
- 约 49 分钟的真实录播共 123 块。第一遍有 1 块遇到模型重复输出；同一音频通过自动缩短重试后成功。全部结果拼接出 1387 条字幕，文字保留、时间顺序、每行最多 22 字检查通过（SRT 毫秒精度允许 1 ms 的舍入误差）。
- 首次复核使用首轮的 122 块和经过实际新进程恢复的 1 块，替换前后音频 SHA-256 一致。之后最终封装程序已从头独立完成整场强制离线运行：123/123 块、1 块自动恢复、1387 条字幕，识别和对齐约 1982 秒（33 分钟）。最新整理逻辑重放所得字幕与该完整运行逐条相同。
- 对齐模型有时将语气词量化成零时长。新逻辑保留同起点的不同文字，必要时分行显示，不丢弃后面的整句，也不逐条推迟字幕。
- 长句在中文词语边界间拆分，例如“其实我们需／要买摄像头”已修正；真正的停顿和完整短句保持分开。
- 实际运行中的取消测试约 0.27 秒退出，工作进程已回收。
- 失败片段已在强制离线环境中完成自动恢复、识别和对齐。模型下载完成后的运行不需要付费或云端识别 API。
- 已检查新界面的方案切换、语言/词汇设置保存与中文布局。替换正常启动文件后再次验证了窗口启动及实际高精度父/子进程流程。

在 32 GB RAM、RTX 3050 Ti 4 GB 显存机器上运行，当前高精度流程使用 CPU 完整精度。首轮整场识别进程观测到的峰值工作集约 9.8 GB。
