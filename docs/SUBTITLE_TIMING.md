# 字幕断句与时间轴修复

## 已定位的问题

- 旧逻辑按显示文字数量匹配时间戳，标点也会占一个字；当数量不一致时，会丢弃可用的声学时间戳，改为在整句时长中平均分配。复现中，一条原本应在 120.8 秒结束的字幕被延长至 124 秒。
- 短于字数上限的句子直接作为一条字幕，不检查其中的句号或明显停顿；长句均分字数时也会越过句界。
- 时间轴整理会把独立单字接到下一句，例如“好。”和“下一句开始”被合成“好下一句开始”。
- 重复起点的字幕会被向后推迟，现改为保留排序后的首条，裁剪其他字幕的重叠结尾，不移动后续字幕的声学起点。

## 修复行为

显示文字与声学 token 分开对齐，标点不消耗时间戳。兼容中文连续文字、空格分隔的 token、中英混排、数字和英文 BPE 单元；只在同一个声学 token 内分配字符位置。无论句子长短，都优先使用字词时间，并按标点或至少 0.6 秒的停顿分句，再在句内按字数拆分。

不再跨句合并单字字幕。音频块仍使用原始 WAV 中的绝对起点还原时间，不累加前一条字幕的时长。

如果模型确实未提供可对齐的时间戳，仍只能在当前句的时间范围内估算，并明确记录警告。本修复不能保证模型对所有口音、背景音乐和语义断句都正确。

## 验证

在项目目录运行（需要 Python 3.10 及 numpy）：

```powershell
python -m unittest discover -s tests -v
```

9 项测试覆盖句界、停顿、中英数字混排、缺失时间戳、重复起点，以及通过完整转录调度流程模拟两小时、60 个音频块的绝对时间定位。修复前的四项核心复现均失败，修复后全部通过。

发行程序验证：

- 从新 EXE 提取实际打包模块执行同一组测试，9 项通过。
- 离屏启动主窗口成功，确认使用程序目录内的 FFmpeg 和 FFprobe。
- 使用本机中文语音合成制作同一段语音，分别放在 0 秒与 125 秒处，经实际 CUDA/FunASR 识别得到两组对应的 4 句字幕。对应字幕起始时间的间隔误差最大约 20 毫秒，结束时间最大约 100 毫秒；未出现累积漂移。
- 以上为可重复构造的音频验证，尚未取得用户出现问题的原始视频与 SRT。
