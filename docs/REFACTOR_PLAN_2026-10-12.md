# 录播助手重构与识别升级计划

日期：2026-10-12。用户已选择：**中文录播准确率优先，允许更慢，本地离线运行**。

## 已核实的起点

- 源码仓库：`G:\录播助手\source\lubo-assistant`；上级目录是现有 Windows 发行包。已有大量未提交代码，须保留其内容，不能 reset、覆盖或删除。
- 现有默认已经是 Qwen3-ASR 1.7B + Qwen3-ForcedAligner 0.6B，CPU 完整精度分阶段运行；Paraformer 是快捷备选。这次升级必须以 Qwen 为质量基线。
- 本机 i7-12650H、31.7 GiB 内存、RTX 3050 Ti Laptop 4 GB。产品约定是 4–6 小时录播、两阶段生成 SRT/烤入成片、保留手工修改字幕及源素材。
- 已有固定 WenetSpeech 256 段、1194.96 秒、5295 字：Qwen 错误 266 字（CER 5.0236%），Paraformer 错误 398 字（7.5165%）。这是本项目固定小样本结果，不能等同作者全量基准。
- 系统 Python 3.10 的基线测试：44 项，33 通过、1 失败、10 错误。缺少 rapidfuzz 导致评分测试错误；缺少 jieba 导致中文词语断句测试失败；系统也缺 torch/transformers。这是源码运行环境不完整，尚不能判定代码回归。

## 模型决策

**首选新增候选：FireRedASR2-AED。** 作者同表普通话四集平均 CER 3.05%，Qwen3-ASR 1.7B 为 3.76%；WenetSpeech NET 为 4.57% 对 4.97%，MEETING 为 4.53% 对 5.88%。它提供字词时间和置信度，适合做可审计的字幕识别 adapter。

这只是筛选依据，不能现在就宣称替换后必然更好。先接入、同素材评测，再决定默认值；未通过质量门槛的候选可保留为明确标注的可选模型，不能静默取代已验证的 Qwen。

- 在独立运行环境中验证 FireRed，固定代码 revision 和权重校验；不能用上游 requirements 覆盖现有 Torch/Transformers。上游 README、pyproject、requirements 的 Python/依赖要求目前不一致。
- FireRed 权重约 4.73 GB；优先 CPU FP32、batch=1，分段推理。4 GB 显存不保证能放下完整模型，不把量化或强制 GPU 作为默认准确率方案。
- 第一轮用当前音频窗口和 Qwen 对齐保持评测可比性；同时验证 FireRed 自带词级时间的文字覆盖和边界质量，合格后才减少额外对齐。不能以均匀分配字数伪造时间戳。
- Qwen3-ASR 1.7B 保留用于基线和回退；Paraformer 保留快捷兼容。FireRedASR2-LLM 等更大模型留作后续实测，不承诺本机资源与收益。
- 词汇提示必须按模型真实能力展示；不能把不支持的提示静默忽略，也不以语言模型润色改写识别原文。

官方依据：[FireRedASR2S](https://github.com/FireRedTeam/FireRedASR2S)、[权重](https://huggingface.co/FireRedTeam/FireRedASR2-AED/tree/main)、[依赖声明](https://github.com/FireRedTeam/FireRedASR2S/blob/main/pyproject.toml)、[Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR)。

## 分阶段实施

### P0：可复现基线与保护

1. 保存开始前的 tracked diff 和非忽略未跟踪源码清单/备份，记录当前 EXE 哈希，不修改现有正常启动文件。
2. 建立隔离测试环境；区分基础 GUI、Qwen、FireRed、评测、打包依赖。先让现有 44 项测试有完整环境并通过。
3. 固定现有评测清单及音频哈希、评分规则和基线模型 revision；记录依赖/硬件信息。

完成条件：测试可复现，现有来源、SRT、配置和发行包可恢复；不把依赖缺失隐藏成跳过测试。

### P1：识别 module 与候选模型

1. 引入小而清楚的识别 interface 与引擎注册表；模型 adapter 承担下载、加载、识别、能力声明和资源释放。
2. 从 `asr.py` 分离公共音频读取及字幕时间/断句 implementation；新模型不再依赖 Paraformer 私有函数。保留必要兼容导出，让旧调用逐步迁移。
3. 高精度录播调度从硬编码 Qwen 路径改为已验证的模型 profile；提供 FireRed CPU adapter、固定下载清单、清晰安装/缺失错误，保持 Qwen 路径可用。
4. 所有模型都通过受控子进程 seam 运行，统一成功/失败/取消与进度数据；避免 GUI 线程直接持有模型。

完成条件：Qwen 回归通过，FireRed 在本机跑通真实片段；两个实际 adapter 证明 seam 的必要性，业务编排不认识模型内部细节。

### P2：长任务恢复与错误诊断

1. 识别工作目录改为持久 job manifest，包含音频指纹、模型 revision、提示/语言、预处理及分块版本；模型或音频变化必须失效旧缓存。
2. 识别与对齐分别逐块原子提交。取消、崩溃后重启只重做未完成阶段；不能将半成品报告标记成功。
3. 保存失败日志，GUI 给出可定位路径；取消终止并回收进程，关闭窗口不无限等待。检测进程异常退出；长 CPU 推理不能仅因暂时无进度就被误杀。
4. 最终 SRT 继续先写 `.part` 再原子替换；手改 SRT 复用必须是明确用户选项，切换模型不自动覆盖。

完成条件：中断/重启、不同模型/参数缓存失效、失败日志保存、缺块不交付、取消回收均有行为测试。

### P3：GUI、流水线与设置

1. 抽出任务控制 module，承接两阶段运行状态、设置快照、启动/取消/收尾；窗口保留展示与信号接线。
2. 从 `pipeline.py` 收拢缓存/产物提交与清理规则，让流水线保留步骤编排。避免只拆成更多转发函数。
3. 公共设置、模型选项、设备策略分开；增加设置 schema 与迁移、枚举/范围校验；旧配置可读。
4. 模型名、精度/设备、首次下载与进度显示真实状态；与当前模型无关的选项禁用或隐藏，不再展示看似生效的分块/设备参数。

完成条件：现有导入排序/资源配对、生成字幕/手工编辑/烧录流程不变；新 interface 提高 depth，使错误修复与测试集中在同一 module（locality），多个调用者共享行为（leverage）。

### P4：同素材质量门槛

1. 先在固定少量片段做运行/完整性检查，再跑现有 256 段固定公开集；参考文本不得输入识别模型。
2. 使用同一 CER 归一化规则，同时评分原始识别与最终字幕；报告错误数、失败样本、总耗时、峰值内存、对齐覆盖和分块边界问题。
3. 候选只有在完整 256/256 成功、CER 低于当前 5.0236%、最终字幕不丢字，并通过配对分组比较时才具备替换默认的证据。若差异不确定，报告原始数据，不伪称显著提升。
4. 对已有真实录播片段做试听/边界检查；缺人工参考时不报告真实录播准确率。公开集通过不等于达到剪映水平。
5. 验证长录播、静音、背景声、重复生成恢复、两小时之后绝对时间及取消。4–6 小时资源行为需有实际样本或明确标注未验证。

完成条件：形成可重现报告，并据结果选择默认模型；若新模型未胜出，明确结论而不为“换模型”降低质量。

### P5：发行验证

1. 更新全量源码构建与依赖收集，验证 worker 入口及模型资源路径；旧 EXE 的 PYZ 补丁只作过渡，不作为长期唯一构建路线。
2. 先输出独立新版本，检查 GUI、首次下载、离线识别、取消、异常恢复、两阶段成片流程；通过后才替换正常入口，并保留已校验备份。
3. 更新运行/构建/模型选择文档，列清真实通过的验证、失败项及未验证范围。

## 2026-10-14 实施结果

识别注册表/adapter、受控子进程、音频与字幕时间模块、持久检查点、产物来源管理、GUI 任务控制和配置迁移已完成。78 项测试无跳过通过；连续取消回收经过 20 个独立进程、500 次重复检查。新增 FireRed 固定环境已安装并完成离线 256/256 识别和对齐，9/9 真实录播片段流程及最终 EXE 的首块取消、剩余块恢复、纯缓存运行也已通过。

固定公开集 FireRed CER 4.5326%，Qwen 5.0236%，少 26 个字级错误；最终字幕没有丢失识别文字。配对分组改善区间 -0.0606 至 1.0397 个百分点，仍跨零，不能宣称普遍显著提升。按用户准确率优先、允许更慢的选择，本机升级版选用本组实测错误较少的 FireRed，并保留 Qwen 回退；源码全新配置与未明确选择 profile 的旧配置仍用 Qwen。这是依据当前点估计的本机部署选择，统计不确定性保留在报告中。

交付入口为 `G:\录播助手\录播助手-重构升级版-v2.exe`。三款原入口未覆盖，真实设置仅添加模型选择字段且有逐字节备份。新入口复用现有 onedir 库，属于已验证的增量发行；干净源码构建和新版 FireRed 的 4–6 小时录播资源表现尚未验证。缺人工参考稿的真实片段不计算准确率。完整记录见 [重构验证](REFACTOR_VALIDATION.md) 和 [模型比较](ASR_BENCHMARK.md)。
